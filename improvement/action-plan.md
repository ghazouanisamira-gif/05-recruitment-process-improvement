# Recruitment Improvement Action Plan

## Improvement Logic

The action plan translated validated findings into a coordinated transformation roadmap.

Actions were not limited to process redesign. They covered **data, sourcing, tools, capability, training, coaching, communication, onboarding and governance**.

| Improvement Area | Expected Outcome | Owner | Priority | KPI | Control |
|---|---|---|---|---|---|
| Process standardization | Reduce variation | | High | Process compliance | Periodic review |
| Recruitment data structure | Improve visibility | | High | Data completeness | Data review |
| Candidate-flow analysis | Identify bottlenecks | | High | Stage conversion | Funnel review |
| Channel strategy | Improve sourcing efficiency | | High | Source contribution / quality | Channel review |
| Automation opportunities | Reduce manual effort | | Medium | Reporting / cycle time | Tool review |
| Role clarification | Improve accountability | | High | Action closure | Governance review |
| Recruitment capability | Improve execution quality | | High | Quality / SLA | Capability review |
| Training & evaluation | Verify skill application | | High | Training effectiveness | Post-training follow-up |
| Coaching | Correct observed gaps | | High | Performance trend | Coaching review |
| Recruitment / Operations alignment | Improve workforce readiness | | High | SLA compliance | Weekly review |
| Onboarding alignment | Improve transition quality | | High | Onboarding completion / early attrition | Handover review |
| KPI implementation | Improve decision-making | | Medium | KPI availability | Monthly review |
| Control routines | Sustain gains | | Medium | Performance trend | Escalation |

## Structured Planning

Because several workstreams ran in parallel, a structured planning rhythm was required to coordinate:

- process actions
- data and reporting
- sourcing / acquisition actions
- tool and automation opportunities
- recruitment team development
- training
- coaching
- onboarding
- governance reviews

The plan connected each action to an owner, timing, expected outcome and control.

## Capability Development Cycle

Training actions followed a broader cycle:

**Need → Training → Application → Evaluation → Feedback → Coaching → Follow-up → Reinforcement**

This made capability development part of operational performance management rather than a separate HR activity.

## Prioritization Questions

- Does the action address a validated cause?
- What outcome should change?
- Who owns implementation?
- What is the expected time to impact?
- What data will demonstrate effectiveness?
- What capability or communication support is required?
- What happens if the KPI remains below target?
- Which actions should be automated or simplified?

## Control Logic

Every significant action should have:

**Owner + KPI + Review Frequency + Trigger + Response**

## Sustainability

Improvement is considered embedded when:

- the process owner can operate it without project support
- KPIs are reviewed routinely
- deviations trigger defined responses
- training needs are identified from performance evidence
- coaching and follow-up are documented
- lessons learned are incorporated into the process
